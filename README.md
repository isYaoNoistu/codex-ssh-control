# codex-ssh-control

在 Codex 聊天侧栏配置 SSH 主机、为每个聊天单独授权，并用图形化界面管理目录、命令、审计和执行历史。需要确认的操作会显示原生确认入口，展开核对分组卡片并批准后自动继续。Codex 留在本机，服务器不安装 Codex 或常驻代理。

项目仓库：[isYaoNoistu/codex-ssh-control](https://github.com/isYaoNoistu/codex-ssh-control)。插件 ID 与仓库提供的本地 marketplace 名称均为 `codex-ssh-control`，安装引用为 `codex-ssh-control@codex-ssh-control`。目前通过仓库安装，尚未收录到公共 marketplace。

## 0.4.0 远程执行基础设施

当前修订版 **0.4.3** 使用原生分组确认卡片，分别展示目的、目标和完整执行内容，长内容支持滚动。排版能力与验证范围见 [确认展示说明](docs/approval-presentation.md)；并发占位和断线发布修复见 [0.4.1 复核记录](docs/review-0.4.1.md)。

- **连接**：可视化 ProxyJump 链路、逐跳固定公钥与 SHA256 确认、保活和连接超时、POSIX 连接复用，以及明确受信任的本机 SSH config 模式。
- **长任务**：提交返回任务 ID；持久状态、增量输出、断线核实、幂等提交、任务停止和资源限制。后台任务默认关闭，需要单独启用并原生批准。
- **制品传输**：两端目录权限、二进制流、断点续传、前缀与完整 SHA256、原子发布到新路径、进度和临时文件清理；目录按清单逐项审批。
- **权限**：精确/递归目录、受管动作目标名称白名单、审批快照、跨进程并发额度，以及撤销后阻止新传输分块和最终提交。

这些配置仍在原有主机详情中完成；执行历史可切换可恢复任务与制品传输。默认不开启新权限，升级保留已有主机和策略。Windows 原生 OpenSSH 不支持连接复用；当前制品通道是受管 SSH 流，尚不提供 SFTP/SCP 协议、覆盖已有制品、PTY、密码存储或密钥轮换。完整行为及限制见 [基础设施契约](docs/infrastructure-contract.md)。

## 权限治理

默认使用受限模式：**非敏感状态查询自动执行；文件修改、启动、停止、重启和删除必须申请；密钥和安全配置禁止访问。**

侧栏有三个页签：

- **主机**：主机配置、启停、连接测试、聊天授权。进入同一个主机详情页，通过“连接设置”和“权限设置”切换连接信息、目录读写、禁止路径、固定操作、命令限制、授权时长、超时、并发数和输出上限；两页分别保存，切换保留未保存内容。
- **审计**：按主机和结果筛选授权、规则变更、审批及执行记录，分页查看。审计不保存文件正文、完整自定义命令或远程输出。
- **执行历史**：紧邻审计，按主机和状态筛选、分页查看操作意义、请求命令、实际执行的完整命令、结果、退出码及经过敏感检查的标准输出和诊断输出（stderr）。详情只展示记录，没有重放执行按钮。

全部设置通过表单、选择框和列表完成，不需要编辑 JSON。权限编辑器内的“检查规则（不执行）”可用尚未保存的设置模拟判断，不会连接服务器。

### 规则优先级

1. 主机必须启用，当前聊天必须具有未过期授权。
2. 核心敏感路径、显式禁止路径和禁止命令优先，不能靠审批放行。
3. 文件操作必须命中配置目录。最具体的目录规则生效；没有配置目录就没有文件访问权。
4. 固定的非敏感状态查询可以自动允许，也能单独改为申请或禁止。修改操作最低为“申请”，不能设为自动允许。
5. 需要申请的操作在当前调用中取得与主机、聊天、配置版本、完整操作和操作说明匹配的一次性原生批准。即使同时发起相同操作，也各自绑定自己的确认。

保存权限策略、改变主机连接信息、禁用主机或撤销授权会使相关授权和未执行审批失效。重新启用不会恢复旧授权。已开始的远程操作不会自动撤销。

撤销还会阻止当前聊天中此前未消费的快捷授权请求恢复该主机权限；其他聊天和其他主机不受影响。重新授权需要新的快捷请求或用户确认。升级到 0.3.2 时，旧版本尚未消费的快捷授权请求失效，已保存的主机、权限策略和有效授权保留。

默认授权最长 60 分钟、任务超时 60 秒、每台主机并发 2 个、输出 128 KiB。可视化设置范围分别为 5–1440 分钟、1–300 秒、1–8 个、16–128 KiB。单次原生确认最多等待 120 秒，且不能超过原聊天主机授权的有效期。拒绝、取消、超时或不支持原生确认时不执行；没有侧栏排队批准的替代流程。

### 固定操作与高级 Shell

固定操作包括连接测试、系统概况、磁盘和 inode、内存、监听端口、Docker 容器/资源/磁盘、系统服务/失败服务和单个服务状态；可申请启动、停止、重启指定服务或容器。服务状态只返回有限字段，不读取环境变量和日志。安全服务不能通过修改模板操作。

固定操作使用明确的系统程序路径和干净环境。`df -h`、`docker ps` 等少量完全匹配的只读命令会转换为固定操作；复合 Shell 不会自动放行。

连接设置中的“默认远程目录”用于未指定工作目录的原始命令；命令显式指定的目录优先，显式空字符串使用 SSH 登录目录。固定操作始终在 `/` 执行。权限检查、原生确认和执行历史使用实际生效的目录；默认目录同样受到敏感路径与禁止路径检查。

高级模式可启用“原始 Shell 逐次审批”。**目录规则不能限制任意 Shell 内部访问的文件。** 此模式适合由用户检查完整命令后明确批准的操作，不能作为目录沙箱；可识别的凭据和安全操作仍拒绝。默认关闭。

### 文件访问

文件工具需要远端现有的 `/usr/bin/python3` 和支持 `openat2` 的 Linux 内核（通常 Linux 5.6+，以实际系统调用可用性为准）。每次操作通过 SSH 标准输入发送临时执行代码，不落地安装服务；不具备条件时拒绝执行，没有退回 `cat` 的旁路。

授权根和子路径不跟随符号链接，子路径不能跨挂载点；拒绝硬链接、设备、FIFO、socket 和带 setuid/setgid 的文件。只处理最多 128 KiB 的 UTF-8 文本。目录列表有条数和输出限制，隐藏保护路径及非普通文件。删除只支持单个普通文件，不递归删除目录。

写入使用同一已打开父目录中的临时文件原子替换，保留现有普通权限和属主/属组；无法保留时失败。具有 ACL 或扩展属性的文件拒绝覆盖。新文件权限为 `0600`。检测到已知凭据格式时，读取不返回内容，写入或覆盖不执行。

`.docker` 属于核心保护目录。Docker 配置中的 `auths` 认证内容即使改名或放在自定义目录，也会进行敏感检查；Base64 用户名密码不能作为普通配置内容返回。

## 使用

1. 打开 **codex-ssh-control / SSH 主机** 侧栏，添加服务器地址、用户名和端口，或复用本机 SSH config 别名。只记录私钥路径，不读取或展示私钥内容。
2. 启用主机，进入主机详情的“权限设置”，按需添加允许读取/写入的远程绝对路径。连接信息与权限共用一个配置页面，默认没有文件目录权限。
3. 保存规则后，选择时长并授权给当前聊天。可点击“测试连接”；不会自动测试或自动接受 SSH 主机公钥。
4. 在聊天中提出任务。智能体先解释目的和预期影响，再提交操作。状态查询按策略自动通过；需要确认时，点击“查看并确认操作”展开原生卡片，核对目的、目标、请求命令和实际完整命令；文件修改显示路径和写入内容。点击“执行一次”后同一调用自动继续，不需要重试。关闭详情仅收起；放弃本次请求请点“取消”。

多主机可同时授权，每次远程操作明确 `hostId`。授权只属于宿主提供的当前聊天；新聊天、fork 和子代理不继承。

`ssh_exec`、`ssh_run_action`、写入和删除工具要求填写 `explanation`，说明具体目的与影响；读取、列目录、连接测试可使用固定操作说明。说明用于帮助用户理解，不会改变权限判断。界面里可以在“执行历史”查看后续结果，异步操作完成后自动写入历史。

### 执行历史与数据保留

每条历史保存执行时的主机和操作快照；标准输出与错误输出合计最多保留 **32 KiB**，超出时明确标为截断。检测到已知凭据格式时，两路输出一起隐藏并标明原因。最多保留最近 **500 条已结束记录**，清理超过 **30 天**的已结束记录；正在运行的记录不按这两个条件清理。

执行历史不保存文件读取或写入的正文：读取只记录路径、字节数和结果摘要，写入记录字节数和内容摘要哈希。历史不会保存远端辅助脚本或其标准输入。等待原生确认时，本机审批记录短暂保存精确操作以供核对；批准、拒绝、取消、过期或失效后清除正文。历史会保留真正进入执行流程的完整命令，请保护本机状态目录。

租约超时且未收到结果时，记录显示“未知”，不把未知当成远端成功或失败；之后收到真实完成结果可补全一次。升级前没有保存的输出无法补回，旧记录不会补造执行历史。

### 快捷授权

整行单独发送 `/ssh-prod /ssh-uat` 或 `$ssh-prod $ssh-uat` 可以追加多台授权；`/ssh-revoke-prod` 撤销，`/ssh-status` 查看。不能混入自然语言、代码块或换行。

快捷授权依赖已信任的 `UserPromptSubmit` hook，其意图有效期 120 秒并绑定当前轮次。从技能 picker 选择 `ssh-prod`、hook 未工作或意图缺失时，会通过 Codex 原生确认申请。加载技能本身不代表已授权。

主机技能生成到 `~/.agents/skills/ssh-主机ID/`。生成器只更新可验证归属且没有人工修改的文件，不覆盖同名用户技能。技能不包含地址、用户名或私钥路径。

## 环境与安装

| 项目 | 要求 |
| --- | --- |
| Codex | 插件、thread 侧栏、MCP Apps、可信聊天元数据；主机授权及需确认的操作要求 elicitation |
| 本机 Node.js | 24+，使用内置 SQLite，无 npm 运行时依赖 |
| 本机 SSH | OpenSSH `ssh` / `ssh.exe` 在 PATH 中；非交互密钥或已解锁 agent |
| 远端命令 | Linux、POSIX 登录 shell、固定系统工具；Docker/systemd 操作需对应组件 |
| 远端文件工具 | Python3、Linux openat2；无需安装 Codex |

先克隆仓库，再使用实际支持插件命令的 Codex 可执行文件安装。桌面 backend 与 npm CLI 可能是不同版本；将下方的 `$CODEX_BINARY` 替换为本机受支持版本的实际路径。

```powershell
git clone https://github.com/isYaoNoistu/codex-ssh-control.git
Set-Location codex-ssh-control

$CODEX_BINARY = 'C:\path\to\supported\codex.exe'
$PLUGIN_PATH = (Get-Location).Path
& $CODEX_BINARY plugin marketplace add $PLUGIN_PATH --json
& $CODEX_BINARY plugin add 'codex-ssh-control@codex-ssh-control' --json
```

重新加载插件后打开侧栏，使用 `ssh_status` 返回的版本核对当前聊天实际加载的插件。manifest 版本只应在发布代码准备完毕后更新，避免桌面提前缓存未完成的版本。

### 从旧名称迁移

如果此前安装了 `ssh-control@ssh-control-local`，先在 Codex 插件设置中停用旧插件，再安装 `codex-ssh-control@codex-ssh-control` 并重新加载。两者不要同时启用，以免重复注册工具和快捷授权 hook。

更名保留 `~/.codex/ssh-control/` 数据目录、`SSH_CONTROL_DATA` 和 `SSH_CONTROL_SKILLS` 环境变量，以及 `/ssh-主机ID`、`/ssh-revoke-主机ID`、`/ssh-status` 快捷指令。原有主机、权限、审计和历史仍从同一份数据读取；不要为更名删除数据目录。

### SSH 登录准备

连接始终使用非交互认证与严格主机公钥校验。受管模式在侧栏为目标及每一跳核对并固定公钥，使用独立 known_hosts。兼容/原生别名模式继续使用 `UserKnownHostsFile=~/.ssh/known_hosts`，覆盖 SSH config 的自定义 known-hosts 位置，但不修改用户 SSH config；首次使用须由用户在终端核验服务器指纹后建立信任：

```powershell
ssh -o StrictHostKeyChecking=ask -o UserKnownHostsFile=~/.ssh/known_hosts -i KEY user@HOST
```

替换占位符，非默认端口加 `-p PORT`；使用默认密钥/agent 可省略 `-i KEY`。插件不接收登录密码或密钥口令。连接测试最长 20 秒，不验证默认目录或写入权限。

## 安全边界

- 本插件治理的是 **codex-ssh-control 的全部远程入口**，不会拦截 Codex 本地 shell、其他 MCP 或其他插件。需由 Codex 宿主/操作系统另行约束本地工具、SSH 私钥和插件状态目录。
- 主机管理、策略保存、审计及历史查询依赖可信宿主的 app-only UI，操作确认依赖宿主的原生 elicitation。每个 MCP 进程的 UI capability 只防止普通模型工具调用伪造管理参数；能读取 UI 资源并任意调用 MCP 的客户端、或拥有同用户文件权限的进程不在隔离边界内。
- 假设远端 OS、系统程序及管理员可信。目录 FD 绑定防止链接/路径穿越，但不防远端 root 主动搬移目录、替换系统二进制或修改挂载。不要把它当成抵御恶意远端管理员的沙箱。
- 内容检测只识别已知格式，不能保证发现任意命名/编码的秘密。应将密钥放在独立受保护目录，并使用最小权限 SSH 账号。写入应用代码或启动已有服务可能产生间接效果，审批者应核对实际操作。
- 取消/超时结束本机 SSH 进程，远端已完成操作不会回滚，脱离会话的后台进程可能继续。状态与审计不是远端执行的事务回滚机制。
- 插件外修改 SSH config 别名、密钥或 agent 不会触发连接版本检测；变更后重新核对目标和授权。

状态默认保存在 `~/.codex/ssh-control/`，可用 `SSH_CONTROL_DATA` 指定；主机技能目录可用 `SSH_CONTROL_SKILLS` 指定。原生确认中的临时正文和执行历史都属于本机敏感状态；审计最多保留最近 5000 条。不要提交实际主机数据、数据库或凭据。
