# 0.4.1 代码复核与修复

2026-11-03，复核 `fa7dc47..af3e875` 的基础设施增量，重点检查聊天/主机身份、审批快照、撤销与并发占位、源/前缀校验和最终发布恢复。以下问题均先用回归测试复现，再修复。

| 严重度 | 位置 | 已确认的问题与修复 |
| --- | --- | --- |
| P1 | `src/infrastructure-runtime.mjs:87`、`src/job-service.mjs:80`、`src/transfer-service.mjs:106` | 源文件校验失败和并发幂等键冲突会留下没有实际任务的持久并发占位；授权后立即撤销也会遗留未下发许可。现在完成预检和去重后才同步绑定持久任务，未下发失败结束本次许可。已下发但结果未知的任务继续保留占位。 |
| P2 | `src/transfer-service.mjs:152` | 发布成功但确认丢失后，如果源已删除或变化，原先提前校验源会使 `commit_unknown` 永远无法核实。现在先验证本传输的提交凭据/已发布 inode 和摘要，只有确实需要继续复制时才校验原源文件；不会重放发布或覆盖目标。 |
| P2 | `src/infrastructure-runtime.mjs:15` | 对外传输记录缺少 `hostId`，侧栏因此无法匹配已授权主机，恢复/取消按钮一直不可用。所有传输响应现在返回审批快照中的主机 ID。 |
| P2 | `ui/panel.html:756` | 授权撤销后，侧栏仍强制远端刷新任务详情，导致连已缓存日志也无法查看。现在失去授权或禁用主机时使用 `refresh:false`，远端控制继续禁用。 |
| P2 | `ui/panel.html:261` | 从受管/原生模式切回兼容模式时，表单省略 `connection`，服务端合并保存后仍保留旧模式。现在明确提交 `connection:null` 清除旧连接设置。 |
