# 审批内容分区（0.4.2）

原生确认保留一次勾选、接受或拒绝的即时流程。执行目的独立放在 `message`；目标主机、实际操作、工作目录、命令/文件内容和本次确认提示放在 `confirm.description`，以空行和文字标签分区。主机访问授权也使用独立标题与分区说明。

命令、文件内容和任务选项来自原有审批快照，原样传递，不省略、不改写，也不放入可编辑的输入框。服务端仍只接受当前请求的 `accept` 与 `confirm === true`，审批绑定、撤销检查、并发限制和执行路径保持不变。没有增加待审批页面或额外的聊天确认。

聊天前的说明使用“执行目的”引用块、独立目标信息和已知原始命令的 `bash` 代码块。受管操作只列已核实的操作和参数，不要求智能体猜测插件生成的命令。`explanation` 始终是普通文本。

## 已核实的宿主能力

2026-11-03 对已安装的 Codex Desktop 26.1027.3384.0 做了只读代码检查。其普通 MCP form 将 `message` 渲染为中等字重标题，将单 boolean 的 `description` 渲染为正常字重、保留换行的正文；两者均不解析 Markdown/HTML。因此原生框使用文字分区，不发送会直接显示出来的代码围栏，也不宣称支持绿色卡片或语法高亮。

该版本另有 `openai/confirmation` 展示扩展，但会增加点击入口再打开弹窗的步骤，且不支持代码高亮。本次未采用该未公开稳定的扩展，也未修改 Codex 客户端。

## 验证与边界

- Windows Node.js 24.13.0：`node --test test/*.test.mjs` 共 361 项，359 通过、2 项平台跳过、0 失败；`npm run check` 通过。首次沙箱运行的文件链接/原子操作受到 `EPERM` 限制，使用正常本机权限重跑隔离套件得到上述结果。
- MCP 测试核对目的在前、完整原始/实际命令、目录、文件正文、任务选项和各主机授权时长没有遗漏。
- 保留并运行批准一次执行一次、拒绝/取消不执行、策略变化及撤销使旧确认失效的回归用例。
- 使用从已安装客户端提取的渲染函数做隔离 JSX 检查，核实单字段的目的、正文和勾选标题各出现一次。该检查不是在真实服务器执行操作，也不等同于真实窗口逐项验收。
- 大正文的协议文本保持完整，但此 Codex 版本把单字段说明放在不可滚动的 header，极长内容可能被宿主容器裁剪。这是现有原生表单的限制，不能把“文本未截断”作为“长文件正文已完整可视审阅”的证明；此改动不宣称修复该宿主限制。

升级客户端后需重新检查原生确认显示；本次不推断其他 MCP 客户端会采用同样的字重或布局。
