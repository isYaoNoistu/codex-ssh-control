# 原生分组确认卡片（0.4.3）

普通确认表单把说明渲染为浅灰小字，不利于核对命令。0.4.3 使用 Codex 的原生只读分组卡片，用户先点击“查看并确认操作”，再核对并选择“执行一次”或“取消”。此交互由用户明确选择；没有增加侧栏待审批队列或执行后的手动重试。

## 展示与交互

- 第一张卡片：执行目的、主机、实际操作、工作目录或目标路径。
- 第二张卡片：完整命令/文件内容/执行选项，以及本次确认的范围。
- 正文使用宿主正常字号和主要文字颜色；保留换行，长内容所在弹窗可滚动。变更操作使用原生警示色确认按钮。
- 标题采用简短的实际操作摘要；过长摘要仍完整保留在目标信息中。卡片不支持 Bash 高亮或任意 CSS，不伪造这些效果。
- 点击关闭按钮或 Escape 只收起详情，不执行、也不取消请求；要放弃操作应点击“取消”。原有最多 120 秒的确认期限从请求发出时开始，展开详情不延长期限。

主机访问授权同样分组展示主机及各自授权时长、权限范围和确认说明。聊天前的说明继续使用目的引用块和已知原始命令的 `bash` 代码块；受管操作不要求智能体猜测生成命令。

## 完整内容与安全边界

`src/approval-presentation.mjs` 从同一份审批快照生成完整 `message` 和 `_meta["openai/confirmation"]` 展示。原有 form 的 `confirm` 仍是唯一必填 boolean，默认 false。只有当前请求的 `accept` 与 `confirm === true` 才能进入原来的审批消费、撤销检查和执行路径。打开详情不是批准，展示字段不是可编辑输入。

宿主展示扩展限制为最多 20 字段、每个值最多 10000 UTF-16 单元。大内容按连续片段展示，不拆开 Unicode 代理对或 CRLF，也不截断命令或正文。空文件和纯空白文件用明确标注的 JSON 转义表示。超过字段预算或出现纯空白片段时，明确使用原生可滚动弹窗的完整文本视图，防止宿主静默丢弃字段。

完整 message 始终保留目的、目标、全部操作内容和确认范围。忽略此扩展的客户端仍可使用普通 form；没有宣称该客户端也拥有卡片或滚动效果。特别是旧式普通表单在 Codex 中的长 header 裁剪限制不等同于原生卡片弹窗的滚动能力。

## 验证范围

2026-11-03，在已安装的 Codex Desktop **26.1027.3384.0** 上只读核实 `openai/confirmation` version 1 的传递、schema、只读卡片、可滚动容器和接受/取消路径。此扩展来自当前宿主实现，不宣称是所有 MCP 客户端的稳定公开接口，也没有修改 Codex 客户端。

使用实际导出函数的请求数据，经提取的真实宿主 schema 解析，再用原生正文渲染函数与宿主 CSS 做隔离 Chromium **145** 检查。桌面浅色、390px 窄屏浅色、桌面深色共 **18 个组合**，覆盖普通操作、主机授权、128 KiB 文件、空文件、纯空白及超过字段预算的回退。检查字段值、正文保留、文字颜色、无横向溢出，以及滚动到末尾后确认按钮可达。预览外框/按钮是示意；这不等同于真实聊天中人工点击审批验收。

Windows Node.js **24.13.0**：完整回归 **364 项，362 通过、2 项平台跳过、0 失败**；最终标题调整后相关展示和审批测试 **29/29** 通过。`npm run check` 通过。回归覆盖接受一次只执行一次、拒绝/取消零执行、撤销与策略变化使旧批准失效、并发隔离和兼容 form 回复。测试使用临时目录、模拟 SSH 和隔离渲染，没有为验证界面执行真实服务器操作。

升级 Codex 后需要复查原生卡片入口、滚动、确认和取消行为；安装版本与当前聊天实际运行版本分别核对。
